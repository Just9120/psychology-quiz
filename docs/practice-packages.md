# Учебная практика через внешнюю модель

Это отдельный контур E10, а не новая категория вопросов «Кейс». Пакет собирается только из опубликованного approved case с действующим publication review и полным contextual breakdown. Изменённый или неподтверждённый материал не экспортируется. Новое содержание кейса во время упражнения приложение не генерирует.

## Подготовка

Рабочая папка — корень репозитория; Python environment и installation указаны в [README](../README.md#быстрый-старт-и-проверки). API, база, внешняя модель и её ключ не нужны для экспорта.

```bash
python scripts/export_practice_package.py   --case-id case_first_consultation_001   --output data/practice-first-consultation
```

Output должен быть новым прямым подкаталогом ignored `data/`. Существующий пакет, путь вне этой папки или symlink отклоняются; при незавершённой записи сохраните её для проверки, не повторяйте команду с тем же output. Кейс и история ответов не меняются.

## Передача и разбор

1. Прочитайте `student-brief.txt`: это вводная и задача ученика, без правильного ответа или критериев оценки.
2. Передайте выбранной внешней модели только `client-role.json`. В нём находятся вымышленная ситуация, условия и инструкции отвечать от имени клиента. Модель не должна подсказывать консультанту методы, критерии или скрытый контекст роли. Приложение не может гарантировать выполнение инструкции внешней моделью и не обещает технической секретности от пользователя, который читает экспорт.
3. Проведите учебный диалог во внешней модели. Не добавляйте реальные персональные данные клиентов. При существенном изменении условий исходный разбор не становится универсальным правилом.
4. После завершения отдельно передайте `transcript-analysis.json` и, при необходимости, вручную добавьте вымышленную переписку в выбранной внешней модели. Пакет содержит материалы и критерии опубликованного кейса, требует опоры на наблюдаемые реплики, различения фактов/интерпретаций/альтернатив и явного указания недостатка данных. Feedback учебный: не диагноз, не квалификационная оценка и не замена супервизии.

`session.json` — полный структурированный пакет для локальной проверки/владельца: версия, fingerprint, вводная ученика, роль клиента, материалы, ограничения, критерии и отдельный пакет анализа. Не передавайте его целиком модели, которая играет клиента: материалы разбора предназначены для следующего этапа.

## Границы данных и проверки

Экспорт сохраняет только учебный текст опубликованного кейса. Drive ID, source refs, исходные файлы, приватное review и ответы пользователей в него не входят. Fingerprint позволяет сопоставить пакеты одной редакции без раскрытия источников. Транскрипт не принимается через CLI/API и не хранится приложением; нет встроенного LLM API, платных запросов или автоматической передачи данных внешней модели.

Canonical адресная проверка из корня: `python -m pytest tests/test_practice_packages.py -q`. Она проверяет reviewed-only gate, отсутствие подсказок из критериев во вводной/роли, private-source boundary, неизменность content, readback и запрет перезаписи/outside output. Поведение выбранной внешней модели требует отдельного ручного упражнения; успешный экспорт не доказывает её качество. Voice-практика остаётся условным AC-PRC-05 и не включается этой процедурой.
